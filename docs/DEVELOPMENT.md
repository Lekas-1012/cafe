## Vibe Coding 工作流程

### 1. 從任務提煉可驗收行為

使用者已提供完整概念與限制，因此直接將需求落為可執行條件：手沖壺必須能直接拖曳；水流與落點連續；停水仍有時間、排水、萃取；玩家自行收尾；過程不顯示秒數或水量；不同策略有不同結果。

規格重點同時映射到程式模組與測試，而非只建立展示頁。

### 2. 建立模型與主要介面

先確認資料夾為空，再建立入口、樣式、三個腳本模組、向量圖示與測試資料夾。模型先處理分區粉床、注水、吸收、排水、分段、悶蒸與權重評分。介面採米白紙感、森林綠、木質托盤與原創器具向量，沒有依賴圖片網站或付費素材。

### 3. 接上直接操作與動畫

水壺以 SVG 按鈕提供可靠的互動目標；Canvas 繪製水流、粉床、氣泡、滴漏及分享壺。壺嘴與落點使用共同幾何，資料與畫面互相對應。操作抓取基準固定於 pointerdown，搭配 Pointer Capture，防止重新抓取跳位與拖出後卡住。

### 4. 以反例檢查評分

建立空杯、少量水、持續猛灌、過量、中央單點、無充分悶蒸、合理分段等確定性案例。初版合理掃動約 84 分，顯示傾角同時控制流量與前後位置時，玩家容易為了照顧不同區域而落入過慢／過強的操作區間。

實際調整前後落點與傾角的映射，讓中等水流也能掃過粉床；調整內部時間中心到與遊戲節奏一致的位置。合理案例提升至 93 分，同時保留單點與無悶蒸的明顯差距。沒有充分悶蒸的短停頓加上成績上限，避免用極短放開冒充悶蒸。

另加入落點過快的抖動懲罰、少水完整度、漏失與溢出懲罰，以及空杯五項指標歸零。

### 5. 用實際瀏覽器操作找錯誤

測試以 HTTP 的 `/coffee-brewing-game/` 子路徑載入，實際操作按鈕、拖曳、鍵盤、教學、暫停、結算與再挑戰。

測試發現 390px 首頁有橫向溢出，原因是裝飾 Canvas 超出容器；修正裁切範圍，並把窄螢幕首頁改成較易讀的單欄。教學關閉及狀態文字屬於非同步更新，測試改為等待真正的 UI 狀態，避免在更新前過早斷言。

測試截圖時也觀察到完整頁面擷取可能調整視窗，觸發既有「縮放時停水」保護；注水截圖改成當前 viewport 擷取，確保保存實際傾壺與出水畫面。這項處理只修正測試方式，不移除遊戲的操作保護。

### 6. 完整一杯與部署準備

追加逐幀測試時鐘，以真實滑鼠事件完成分段掃動、悶蒸、等待及收尾，不直接改寫遊戲內部狀態。實測可取得超過 85 分的高分，確認模型的高分路徑能經由正式操作達成。另驗證最佳紀錄更新與重新載入後保留。

整理規格、使用方式、部署步驟、成果草稿與測試清單。2026-10-17 透過 winget 安裝 Git 2.55.0 與 GitHub CLI 2.102.0，為目前 Windows 使用者建立 ED25519 金鑰，使用 GitHub 官方裝置登入流程授權 `Lekas-1012`，並把公鑰上傳到該帳號。專案初始化為 `main`，推送到公開 Repository `Lekas-1012/cafe`，Pages 發佈來源設為 `main / (root)`。

GitHub 回報 Pages 建置狀態為 `built` 後，另以 HTTP 檢查首頁、CSS、SVG 與八個遊戲 JavaScript 資源皆回應 200；乾淨的無頭 Chrome 從 `https://lekas-1012.github.io/cafe/` 載入，確認主程式全域、開始按鈕、選豆畫面與六款豆卡正常，沒有 Page Error、Console Error、失敗請求或 4xx／5xx 回應。公開站完整長流程仍列為人工驗收項目。

## 問題與修正對照

| 實際問題 | 修正方式 |
| --- | --- |
| 傾角兼顧流量與前後落點，初版合理操作分數偏低 | 校準映射及時間參數，用合理案例與反例一起驗證 |
| 短暫鬆手可能灌出大量假分段 | 合併很短的停頓，極短悶蒸設總分上限 |
| 拖曳超出或視窗失焦可能卡住出水 | Pointer Capture、cancel／lostcapture／blur 停水與暫停 |
| 返回分頁可能補算離開時間 | 可見性事件凍結，明確繼續後重設時間基準 |
| 手機首頁出現水平溢出 | 限制視覺容器溢出，窄螢幕調整單欄 |
| 結算秒數四捨五入可能顯示 60 秒 | 先四捨五入總秒數，再拆成分與秒 |
| localStorage 不可用可能中斷遊戲 | 讀寫 catch，使用當次記憶體紀錄繼續遊玩 |
| 首頁靜態插畫不需每幀重繪 | 改為版面改變或切換畫面時才重畫 |
| 暫停或結算時可能殘留滴漏聲 | 停止操作時直接把音量淡出為零，以實際音量節點補測 |

## 後續調整：視角切換

使用者提出「可以調視角嗎」後，加入場景上方的全景、俯視、近看粉床。俯視不是只放大原圖，而是以圓形粉床重新繪製，同時保留分享壺的咖啡累積小窗。三種視角共用粉床資料與繪製函式，壺身投影和拖曳反向換算也集中管理。切換時先停水，保留原本的萃取進度。

新增 preparation.js 與 preparation-renderer.js，保留同一份豆子的材料量。手柄角度差才會產粉，粉杯出粉口到達濾杯上方且傾斜才轉移粉；輕晃改善密度分布。熱水以遊戲尺度加熱與冷卻，類比指針讀真正溫度，正式／練習分開揭露。

game.js 重構為完整階段轉移，前進除了按鈕停用也檢查準備條件。舊 v1 最佳記錄保留，v2 正式成績與練習分離。指南同步改寫，避免仍教玩家用舊 Y 軸控制位置。

## 補上真正撞倒器具
